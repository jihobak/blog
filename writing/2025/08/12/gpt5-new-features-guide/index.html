    GPT-5에서 추가된 API 기능 살펴보기

    GPT-5가 드디어 출시되었습니다! GPT-5에서 새롭게 추가된 주요 부분들을 간단하게 정리해보겠습니다.

    주요 변경사항 요약

    GPT-5-* API 업데이트:

    • Temperature 파라미터 미지원: GPT-5 계열 모델은 temperature을 지원하지 않습니다
    • Verbosity 옵션: 모델 응답의 길이 3단계로 조절 가능
    • Minimal Reasoning: 추론 토큰을 최소화하여 응답 속도 향상
    • Freeform Tool Calling: JSON 없는 도구 호출
    • Context-Free Grammar: 문법 규칙으로 출력 형식 제어

    1. Temperature 파라미터 변경사항

    GPT-5 계열 모델에서는 현재 temperature 파라미터를 지원하지 않고 1로 고정 되어 있습니다. 기존에 temperature로 모델의 품질이나 창의성을 조절하셨던 분들은 대신 Prompt, 밑에서 등장할 reasoning effort 파라미터나 verbosity 옵션을 활용할 수 있습니다.(GPT-5의 달라진 특성으로 인해 불만이 많자, 현재 ChatGPT에서는 GPT-4o 모델을 다시 추가했습니다.)

    2. Verbosity: 응답 길이의 조절

    기본 사용법

    Verbosity는 low, medium, high 세 가지 옵션을 제공합니다 (기본값: medium):

    def generate_with_verbosity(verbosity, query):
    response = client.responses.create(
        model="gpt-5-mini",
        input=query,
        text={"verbosity": verbosity}
    )
    return response.output_text

    실제 차이점 비교

    "안녕하세요"라는 간단한 인사에 대한 응답 차이:

    Low Verbosity: 

    안녕하세요! 무엇을 도와드릴까요?

    Medium Verbosity: 

    안녕하세요! 만나서 반갑습니다. 어떻게 도와드릴까요?

    High Verbosity: 

    안녕하세요! 반갑습니다 — 무엇을 도와드릴까요?

간단히 예를 들면 다음과 같이 도와드릴 수 있어요:
- 번역(한국어↔영어 등), 문장 다듬기, 이메일·보고서·자기소개서 작성
- 요약(기사·문서), 정보 검색과 설명(역사·과학·법률 기초 등)
- 코드 작성·디버깅(파이썬, 자바스크립트 등), 알고리즘 설명
- 여행 일정·식단·운동 계획 세우기
- 문제 풀이(수학·물리), 언어 학습 도움
- 이미지가 있으면 분석하거나 설명해드릴 수도 있어요(사진 업로드해 주세요)

원하시면 편한 말(반말)로 바꿔 드릴 수도 있고, 더 공손한 표현으로도 도와드릴게요. 무엇을 하실래요?

    흥미로운 관찰: Reasoning Token의 비일관성

    테스트 과정에서 간헐적으로 특이한 현상을 관찰할 수 있었는데, token usage에서 reasoning token 사용량은 0으로 잡히는데 reasoning summary가 존재하는 경우가 종종 관찰되었습니다.('Reasoning Output' 컬럼이 gpt 에서 제공해주는 reasoning summary 입니다)

    🔬 실험 코드 
    def generate_multiple_outputs(query, configurations, model="gpt-5-mini"):
    """
    Generate multiple outputs with different configurations and optionally display them.

    Args:
        query (str): The input query/prompt
        configurations (list): List of configuration dictionaries for different outputs
        model (str): The model to use (default: "gpt-5-mini")
        display_results (bool): Whether to display the results using display_output

    Returns:
        tuple: (raw_responses, formatted_outputs)

    Example configurations:
    [
        {"name": "Low Verbosity", "text": {"verbosity": "low"}},
        {"name": "Medium Verbosity", "text": {"verbosity": "medium"}}, 
        {"name": "High Verbosity", "text": {"verbosity": "high"}},
        {"name": "With Reasoning", "reasoning": {"summary": "auto"}},
    ]
    """
    raw_responses = []
    outputs = []

    for config in configurations:
        # Extract configuration name
        config_name = config.pop("name", "Unknown")

        # Create response with the configuration
        resp = client.responses.create(
            model=model,
            input=query,
            **config
        )
        raw_responses.append(resp)

        # Extract reasoning summary if available
        reason_summaries = []
        for item in resp.output:
            if getattr(item, "type", None) == "reasoning" and getattr(item, "summary", None):
                for seg in item.summary:
                    if getattr(seg, "text", None):
                        reason_summaries.append(seg.text)
        reasoning_output = "\n".join(reason_summaries)

        # Prepare output data
        output_data = {
            "Configuration": config_name,
            "Sample Output": resp.output_text,
            "Reasoning Output": reasoning_output if reasoning_output else "N/A",
            "Output Tokens": resp.usage.output_tokens,
            "Reasoning Tokens": getattr(resp.usage.output_tokens_details, 'reasoning_tokens', 0),
            "Total Tokens": resp.usage.total_tokens
        }
        outputs.append(output_data)


    return outputs

    코딩 작업에서의 Verbosity 활용

    코드의 경우 에도 verbosity 로 인한 차이를 볼 수 있습니다. verbosity 가 높아질 수록, 코드에 대한 주석과 설명의 양이 늘어나는거 볼 수 있습니다.('low', 'medium' 의 경우 당장 잘못된 코드가 생성되었는데, 그대로 두었습니다.)

#!/usr/bin/env python3
"""
Generate and sort N random numbers, timing the operations.

Usage:
    python sort_random.py            # default: 1_000_000 floats, pure Python
    python sort_random.py --n 10000  # change count
    python sort_random.py --numpy    # use numpy if available (faster)
    python sort_random.py --seed 123 # reproducible (Python RNG)
"""

import time
import random
import argparse
import sys

def parse_args():
    p = argparse.ArgumentParser(description="Generate and sort random numbers.")
    p.add_argument("--n", type=int, default=1_000_000, help="How many random numbers to generate (default: 
1_000_000)")
    p.add_argument("--seed", type=int, default=None, help="Optional RNG seed for reproducibility")
    p.add_argument("--numpy", action="store_true", help="Use numpy arrays (if available) instead of Python list")
    return p.parse_args()

    3. Minimal Reasoning: 속도가 중요할 때

    "불필요한 추론 토큰을 줄여 속도를 높이는 옵션"

    빠른 응답이 필요한 상황

    단순한 분류나 추출 작업에서는 복잡한 추론 과정이 필요하지 않습니다:

    response = client.responses.create(
    model="gpt-5",
    input="회사의 CEO가 가장 싫어하는 요일의 하루는 몇시간인가?",
    reasoning={"effort": "minimal"}
)

    4. Freeform Tool Calling: JSON 없는 자유로운 호출

    기존 방식의 한계

    기존에는 모든 도구 호출이 JSON으로 래핑되어야 했고, tools 정의도 다소 복잡했습니다:

    # 기존 방식 - 복잡한 JSON 스키마 정의 필요
tools = [{
    "type": "function",
    "name": "code_exec",
    "description": "Executes arbitrary python code",
    "parameters": {
        "type": "object",
        "properties": {
            "code": {
                "type": "string",
                "description": "Python code to execute",
            },
        },
        "required": ["code"],
    },
}]

# 결과도 JSON 형태로 파싱 필요
python_code = json.loads(response.output[0].arguments)['code']

    Freeform

    GPT-5에서는 type: "custom"을 사용하면 function calling 을 위한 정의 부터, 결과의 parsing 까지의 과정의 간소화 됩니다.:

    ⚠️ 주의: custom tool type은 parallel tool calling을 아직 지원하지 않습니다. 병렬 호출이 불가능하므로, 여러 도구를 동시에 실행해야 하는 경우에는 기존 방식을 써야 합니다.

    response = client.responses.create(
    model="gpt-5-mini",
    input="strawberry에서 'r'의 개수만큼 반지름을 가진 원의 넓이를 계산해줘",
    tools=[{
        "type": "custom",
        "name": "code_exec",
        "description": "Python 코드를 실행합니다"
    }]
)

# 결과: JSON 래핑 없이 직접 Python 코드 생성
print(response.output[1].input)

    5. Context-Free Grammar

    문법 기반 출력 제어

    문법 규칙이 주변 맥락에 의존하지 않는다는 의미로 Context free 라는 의미로 주로 프로그래밍 언어 파싱, 수식 파싱 등에 사용된다고 합니다. 자신이 정한 룰 기반으로 모델의 출력 구조를 조절 할 수 있어서, 후처리, 에러 처리에대한 비용을 줄일 수 있어 보여서 합성 데이터 생성 등 특정 케이스에는 아주 유용하게 사용 할 수 있을 것 같습니다.

    아래 예제는, 보다 쉽게 받아 들일 수 있도록 예시를 들어봤습니다. 쇼핑몰 고객 대응에대한 평가 데이터 셋을 위해 샘플 데이터를 만드는 상황입니다.

    import textwrap

coupang_data_grammar = textwrap.dedent(r"""

    Migration 가이드

    gpt5 모델 부터 오히려 Prompt 의 중요성이 더 높아진 것 같습니다. openai 는 모델이 잘 할 수 있고, 수요가 많은 분야인 코딩, frontend, tool-calling 분야에대해서 자신들의 경험을 녹여내어 가이드를 직접 공유하고 있습니다. 게다가 gpt5 에 더 적합한 Prompt로 바꾸어주는 Prompt Optimizer 까지 만들어서 사용을 권장하고 있습니다.
